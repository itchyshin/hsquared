## 3a. Decisions and Rejected Alternatives

- **NEWS.md consolidated in one PR (#226), not four.** The four builder PRs
  each initially added their own `NEWS.md` hunk; Rose (wave A) required all
  four dropped, because three of the four would have produced conflicting,
  partially-overlapping headers landing in merge order rather than one
  coherent section. Rejected: letting each PR keep its own bullet and
  resolving the `NEWS.md` conflicts by hand at merge time — rejected because
  it produces the same section by accident, several times, instead of once
  by design, and each conflict resolution is a chance to silently drop or
  duplicate a bullet.
- **`max_dense_cells` given a lever-free hint on 13 of 17 wrapped routes,
  not the same hint everywhere.** #220's first draft used one hint constant
  (naming `max_dense_cells`) at all 17 `hs_julia_fit()` call sites. Rose
  found that only two of those routes (`fit_animal_model` default,
  `repeatability`) actually forward the kwarg to an engine entry point that
  accepts it; the other 13 (`multi_effect`, `direct_maternal`,
  `random_regression`, etc.) would tell a user to raise a lever their route
  does not have — and, once #223 landed, following that advice would throw
  `hsquared_unsupported_syntax`. Split into `hs_dense_route_hint` (the two
  guarded sites) and `hs_dense_scale_hint` (the other 13, naming the
  `n <= ~1000` scale recommendation instead). Rejected: adding
  `max_dense_cells` to all 17 routes' formals — rejected because most of the
  underlying Julia entry points (`fit_multi_effect_reml`,
  `fit_direct_maternal_reml`, etc.) either accept no such kwarg at all or
  reach the guard through `fit_payload_v2`'s narrower signature, so an
  R-side parameter with no engine effect would recreate the #212 defect
  class the campaign exists to remove.
- **The dense-cell cap's docs say "under `engine = "julia"`", not "the
  default `animal()` route."** The builder's own PR body correctly found
  that the ordinary default `engine = "fit"` path routes to the
  sparse-capable `fit_ai_reml()`, which enforces no dense-cell cap at all —
  but the first draft of `?hs_control` and `model-status.Rmd` still called
  the guarded route "the default `animal()` route," which an applied R user
  reading their own ordinary `hsquared(y ~ animal(...))` call would
  reasonably (and wrongly) read as describing their call. Rose required the
  correction to both files, and (in wave B) required `NEWS.md` not
  reintroduce the same phrase. Rejected: leaving the correction only in the
  PR body's internal "Defect" section — rejected because the shipped
  documentation is what a user actually reads.
- **`repeatability_interval`'s silent-`NULL` behaviour documented, not
  fixed.** Raising `max_dense_cells` above the default on
  `target = "repeatability"` returns the point fit but silently drops the
  opt-in interval to `NULL`, because `HSquared.repeatability_interval`
  exposes no such control and is called inside a Julia-side
  `try;...;catch; nothing; end`. No R-side fix exists for this (the lever the
  engine would need is on the Julia side); documented the caveat in
  `?hs_control` instead of leaving it undiscoverable.
- **Cross-PR `max_dense_cells` honoured-keys reconciliation done inside #223,
  not as a seventh PR.** Rose measured (via `git merge-tree`) that merging
  #220 and #223 without reconciling `hs_engine_control_honoured_keys` would
  silently revert #220's entire feature with CI staying green (#220's live
  tests are `skip_if_not`-gated and do not run in CI). Rejected: a separate
  reconciliation PR after both merged — rejected because that window would
  ship a real regression to `main`, even briefly; instead #223 (merged last
  of the four builders) carried the fix and merged `main` forward first to
  verify it against the real merged tree.
- **The `all_one`/Poisson fixture wording fix ("half-sib" → "full-sib") made
  text-only in #227's own diff, and one further instance left for later.**
  Rose (wave C) found the shared pedigree in both new fixtures makes the
  named animals full, not half, siblings — fixed in the required change. A
  second, lower-stakes instance of the same slip ("sire families" at
  `test-nongaussian-three-field-v09.R:462`) was recorded but not required,
  and is carried as a residual (§10) rather than fixed here, since it is
  outside the two required changes Rose actually blocked on.

## 9. What Did Not Go Smoothly

- **The first live-suite reading of "FAIL 0" hid five real errors.**
  `devtools::test()`'s `failed` column and its `error` column are different
  things — a `test_that()` block that throws before any expectation runs
  increments `error`, not `failed`. An early check that summed only `failed`
  reported a clean run while five tests were in fact erroring on every
  invocation; the correct picture only appeared once `error` was summed too.
  This became a standing lesson (§11) precisely because it nearly let a real
  regression (the #342 boundary interaction) go unreported.
- **A destructive-command guard tripped on a routine file restore.**
  Dropping the `NEWS.md` hunks required restoring `origin/main`'s content
  into the worktree; the `git checkout origin/main -- NEWS.md` form of that
  step was flagged as discarding another lane's in-flight work and had to be
  done instead via `git show origin/main:NEWS.md > NEWS.md`, which is not a
  guarded git-history command but produces the identical result.
- **Two PRs independently invented the same helper.** `claude/h2-fixer-r2`
  and `claude/h2-fixer-r4` both added a `hs_abort_out_of_range()` helper to
  `R/conditions.R` for two different call sites, discovered only when each
  builder diffed against the other's branch mid-task. Whichever merged
  first turned the other's merge into a small, but real, duplicate-definition
  hazard (git flags the textual conflict but a careless "keep both"
  resolution would silently double-define the function).
- **A background test run died silently on a manual `&`.** One repair round
  appended a stray `&` inside an already-backgrounded shell call; the
  wrapping shell exited immediately and reaped the detached process with it,
  truncating the log at four lines. Relaunching without the extra `&` let
  the tool's own backgrounding carry the run to completion.

## 11. Team Learning

- **Sum testthat's `error` column, not only `failed`, when reading a live
  suite.** `error` (an uncaught condition aborting a `test_that()` block
  before any expectation runs) and `failed` (an expectation that ran and
  did not hold) are different failure modes with different causes; a
  `CHECK` command that reads only `failed` can report "0 failures" while
  real, reproducible errors sit uncounted. This nearly hid the #342
  boundary-refusal interaction from the campaign's own gates.
- **Consolidate a shared file like `NEWS.md` in exactly one PR, named up
  front**, not once per builder — four independent bullets converging on
  one header in merge order is strictly worse than one PR reading each
  merged PR's actual body and writing the section once.
- **Merge `main` forward into each dependent branch; never rebase or
  force-push across a stack of PRs that touch the same files.** Every
  cross-PR conflict in this campaign (the three-way `NEWS.md`/
  `R/conditions.R` conflict, the #220×#223 `R/hs_control.R`/
  `R/julia-bridge.R`/`man/hs_control.Rd` conflict) was resolved this way,
  with CI re-run against each new base before the next PR merged — a rebase
  would have required redoing that resolution invisibly, without CI's
  record of it.
- **Write the conflict-resolution rule before the merge, not during it.**
  Rose's wrapper-vs-forwarding rule ("kwarg-building code stays outside
  `hs_julia_fit()`; the rewritten Julia call goes inside it") and the
  "keep exactly one `hs_abort_out_of_range()` definition" rule were both
  written *before* anyone resolved the actual conflicts, as explicit,
  function-by-function instructions in the audit report. Every conflict
  this campaign hit had a name and a stated rule before a human or agent
  touched a merge marker — the alternative (resolve first, ask later) is
  exactly how a "take both" resolution silently double-defines a function
  or relabels an R-side validation error as an engine error.

## 12. Cross-Product Coverage

`engine_control` gained two new cross-cutting levers this campaign
(`initial`/`iterations` forwarding via `hs_engine_control_forwarding()`, and
`max_dense_cells`), and one existing behaviour (a raw Julia error crossing
the bridge) was replaced campaign-wide by a classed condition
(`hs_julia_fit()`). Each is a transformation that touches every Julia
target, not a feature scoped to one — so the negative space matters as much
as the positive claim.

**`initial`/`iterations` forwarding (#212/#223) covers:** `fit_animal_model`
(default, `initial` only), `ai_reml` (`initial`, `iterations`, `em_warmup`),
`henderson_mme`/`metafounder`/`snp_blup` (`variance_components`),
`sparse_reml`/`repeatability`/`two_effect`/`direct_maternal`/`genomic`/
`single_step`/`single_step_construct`/`metafounder_single_step`/`relmat`/
`precision` (`initial`, `iterations`), `multi_effect` (`initial`,
`iterations`, `scale_method`), `multivariate` (`initial`, `iterations`,
`genetic_structure`, `rank`), `random_regression` (`iterations` only, no
`initial` formal exists), `nongaussian` (`marginal`, `iterations` — **does
NOT cover** `initial`, tracked as hsquared#225). It **does NOT cover** the
`multi_effect`/`scale_method = "auto"` dispatch arm (HSquared.jl#343,
Julia-side, unfixed) — that one path still silently drops both kwargs even
though the underlying fitter accepts them.

**`max_dense_cells` (#214/#217/#220, reconciled with #212/#223) covers:**
`fit_animal_model` (the default Julia target under `engine = "julia"`) and
`repeatability`, both of which reach a Julia entry point
(`fit_variance_components`, `fit_repeatability_reml`) that actually enforces
the guard. It **does NOT cover**: the default `engine = "fit"` path (routes
to the sparse-capable `fit_ai_reml()`, which has no such cap — the lever is
silently a no-op there, by construction, not a bug); `multi_effect` and
`direct_maternal` (their engine fitters *do* enforce the same guard, but
reach it through `fit_payload_v2()`, whose signature has no
`max_dense_cells` parameter to forward — pinned at the engine default `1e6`
with no R-side control); every other of the 17 wrapped routes (no such
guard exists on their Julia side at all, hence `hs_dense_scale_hint` rather
than naming the lever); and `repeatability_interval` specifically, whose
separate Julia entry point exposes no `max_dense_cells` and runs at the
engine default even when the point fit's cap has been raised — raising the
cap above `1e6` on `repeatability` therefore returns the point fit with the
interval silently `NULL`, not an error.

**`hs_julia_fit()` error translation (#214/#217/#220) covers:** the primary
fit-invoking call in all 17 `hs_fit_julia_*_payload()` functions. It **does
